### Telusko Quiz App ###

# Dependencies:
a) Spring Web
b) PostgreSQL Driver
c) Spring Data JPA
d) Lombok

# For DB connection, add following in 'application.properties' file:
spring.datasource.driver-class-name=org.postgresql.Driver
spring.datasource.url=jdbc:postgresql://localhost:5432/questiondb
spring.datasource.username=postgres
spring.datasource.password=postgres
spring.jpa.hibernate.ddl-auto=update
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect

# Create database. Just running the application will not create the DB.

# APIs:
a) GET question/allQuestions  --> get all the questions list
b) GET question/category/{category}  --> get all questions by category
c) POST question/add  --> add a new question
d) DELETE question/{id}  --> delete a question
e) PUT question/update/{id}  --> update a question
f) POST quiz/create?category={category}&numQ={numQ}&title={title}  --> create a quiz
g) GET quiz/{id}  --> get quiz
h) POST quiz/submit/{id}  --> submit right answer of quiz questions and get result back

# Keep all classes in their respective packages at path src/main/java.
Service classes goes in 'service' package.
Controller classes goes in 'controller' package.
Repository classes goes in 'dao' package.
Entities in 'model' package.

# Use appropriate annotations for these classes. Don't just use @Component for Service class, instead use @Service.

# Entities:
a) Question
b) Quiz
c) QuestionWrapper (object to be sent when fetching quiz)
d) Response (request body format when submitting quiz)

# SQL follows snake_casing but in Java, we use camelCasing.So in models we just need to write in camelCasing and the conversion of camelCasing to snake_casing will be taken care of by ORM framework i.e. JPA.

# For 'id', use -> 
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
@Id marks the field as the primary key of the entity. @GeneratedValue(strategy = GenerationType.IDENTITY) tells JPA that the primary key value will be automatically generated by the database using an auto-increment column.

# Use @Data annotation on entities. It is a part of Lombok library which simplifies writing boilerplate code in Java. It automatically provides getters, setters, toString(), equals(), hashCode() and constructor.

# In Repository class, add:
public interface QuestionDao extends JpaRepository<Question,Integer> 
where Question represents the entity which is the table and Integer represents the type of the primary key of the table.

# @GetMapping("category/{category}")   // whatever value you assign in {category} will be assigned to the category param below
    public List<Question> getQuestionsByCategory(@PathVariable String category){
}
But if the url param name does not match the method param name, then it needs to be mentioned with @PathVariable
@GetMapping("category/{cat}")
    public List<Question> getQuestionsByCategory(@PathVariable("cat") String category){
}

# For getting list of questions by category, we just need to add the following method in our Question Repository class:
List<Question> findByCategory(String category);
We don't have to define this method. No! Category is a part of a table. Data JPA is smart enough to understand that the user is trying to find data based on the category column. But if you're going to use customization, then you need to use HQL (Hibernate Query Language) or JPQL (JPA Query Language)

# HTTP Response Status Codes:
Informational responses (100 – 199)
Successful responses (200 – 299)
Redirection messages (300 – 399)
Client error responses (400 – 499)
Server error responses (500 – 599)

# ResponseEntity is used to return data as well as the status code to the client. ResponseEntity will be set in the service class and not in the controller class. Why? Because that way exceptions can also be handled in Service Layer.

# Use @RequestParam for url params

# Relationship between quiz and questions:
It cannot be @OneToOne as a quiz can have multiple questions.
It cannot be @OneToMany as then the same question cannot occur in another quiz. Two quizzes can have same question. So, it will be @ManyToMany.

# When using Optional -> Optional<Quiz> quiz= quizDao.findById(id);
use get() -> List<Question> questionList= quiz.get().getQuestionList();
Or you can also do like this: Quiz quiz = quizDao.findById(id).get(); By using get(), we do not need to add Optional.

# @RequiredArgsConstructor -> annotation in Lombok which automatically generates a constructor with the required arguments for any fields that are final or marked as @NotNull in the class
